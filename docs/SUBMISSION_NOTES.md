# W03 제출 초안

공식 출처: https://axacademy.ai/axwar/samilpwc-1. A04 원문과 제출 화면의 정확한 6문항 제목은 확인하지 못했다. 아래는 **잠정 분류의 초안**이며 실제 문항과 대조·재배치가 필요하다. 각 본문은 1,000자 미만이다.

## 1. 업무 문제·목표 (잠정)
W03 품질 이슈와 공급 복구를 선택했다. 품질팀 회수 판정이 영업 고객 안내·생산 재공급과 분리되는 문제를 해결한다. 고객 주장과 확정 검사를 분리하고 배치 불량률·출하 범위를 근거로 위원회가 결정하면 부서 작업과 계획이 실제로 바뀐다. 내부 DB 처리는 실제, 의결·부서 회신은 시연용 역할로 입력한다.

## 2. 데이터 근거 (잠정)
54개 원본을 헤더·본문으로 조사했다. 이름과 내용 불일치를 확인해 생산은 sales_meeting_notes_cv (2).md, 검사는 fin_ap_aging_ms (2).csv, 배치 출하는 fin_cash_daily_ms (2).csv에서 읽는다. 배치·고객 키를 검증하고 해시·레코드 ID를 보존한다. SBL과 SH는 직접 연결할 수 없어 주문을 임의 귀속하지 않는다. 제조 재고·납기·능력 기간은 확인 대상으로 남긴다.

## 3. 판단·AI·사람 경계 (잠정)
확정 True 수량 합/배치 생산량을 결정적으로 계산하고 10% 이상이면 위원회 심사 대상이다. 언론·미확정 주장은 수량에 더하지 않는다. OpenAI 설정 시 최소 정보로 위험·대안을 구조화 JSON으로 받아 검증한다. 키 부재·실패 시 규칙 기반임을 표시한다. 실제 API 성공 호출은 이번 검증에 포함되지 않았다. 승인·숫자·상태 변경을 LLM에 맡기지 않는다.

## 4. 실제 처리와 예외 (잠정)
접수·분석 버전·의결·배치·업무·계획·감사를 SQLite에 저장한다. 승인 시 영업·생산 작업이 트랜잭션으로 생성되고 동시·중복·자기 승인을 막는다. 거절하면 조사, 추적 부족이면 물류 확인과 회신 후 재분석으로 연결한다. 기존 회수 배치는 승인 이력을 읽어 중복 회수하지 않는다. 숫자·식별자·날짜 충돌은 확인 업무로 남긴다.

## 5. 확장·부서 영향 (잠정)
확장 A는 기록된 출하량의 고객 식별률을 계산해 실행 보류와 물류 확인을 결정한다. 확장 B는 31일 동일 제품·유형 3건 이상을 탐지해 품질 조사 작업을 만든다. 경보 임계값은 가정이며 회수 자동 승인과 다르다. 영업 고객 안내·납품 협의, 생산 여력 확인·재공급 요청이 생긴다. 공급 부족 회신은 고객 배분 부족량과 추가 생산 작업을 갱신한다.

## 6. 검증·한계 (잠정)
Flask·SQLAlchemy·Pandas·SQLite와 한국어 UI로 로컬 실행하며 Node 빌드가 필요 없다. 정상·변경·부족·거절, 동시 의결, 지속성, 권한·입력·API 실패 폴백을 테스트했다. TEST_RESULTS.md에 결과를 기록한다. 외부 ERP·물류·메일, 실제 AI 성공 호출, 영상 촬영·제출, Python 앱의 원격 배포는 미수행이다. 기존 Axhub 주소는 이전 테스트 앱이고 이번 결과물은 소스·로컬 실행판이다.

## 실행 안내
README대로 Python 3.9+ 환경과 requirements 설치 후 app.py 실행, http://127.0.0.1:5000 접속. 접수 담당으로 시연 시작, 위원회로 전환하고 다른 수행자 이름을 적용해 의결한다. 작업은 담당 부서 역할에서 모의 회신. API 키 없이 실행 가능. 테스트: python -m pytest tests -q. 제출 zip에서 가상환경·빌드·instance DB/키·.env·기록 키 설정을 제외한다. 실제 A04·제출 문항 대조가 필요하다.
